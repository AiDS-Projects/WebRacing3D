# PRD — 实现玩家赛车与第三人称跟随视角

> 所属需求：WebRacing3D 可玩原型 — 核心玩法验证

## 用户故事
As a 玩家，I want to 通过键盘或触屏虚拟按键驾驶一辆赛车，并从第三人称跟随视角观察车辆，So that 我能直观判断车辆姿态、朝向与赛道位置，为后续竞速计时与碰撞玩法提供可操作的基础。

## 功能需求
功能点 1：玩家赛车模型 — 使用 Three.js 基础几何体（BoxGeometry/CylinderGeometry/SphereGeometry 等）组合构建可识别的赛车外观，至少包含车身主体、驾驶舱、4 个车轮；车轮作为独立子节点以便后续做旋转动画；赛车整体置于一个 Group 根节点下，便于统一控制位置与朝向。
功能点 2：第三人称跟随相机 — 相机固定位于赛车后方上方（沿车辆后向偏移 + 高度偏移），跟随赛车的位置与朝向；位置与朝向变化采用平滑插值（阻尼/lerp），避免相机硬贴导致抖动；相机始终看向赛车前方目标点；提供可配置的跟随距离、高度、插值系数常量。
功能点 3：键盘输入 — 支持 W/↑ 加速、S/↓ 刹车/倒车、A/D/←→ 转向；按键按下/释放即时更新输入状态，无粘滞；支持多键同时按下（如 W+A 同时加速并转向）。
功能点 4：触屏虚拟按键 — 移动端（触摸设备）显示虚拟按键，至少包含加速、刹车/倒车、左转、右转 4 个按键；支持多点触控（同时按住加速与转向）；虚拟按键按下/释放状态正确映射到与键盘相同的控制信号；仅在触摸设备上显示虚拟按键，桌面端不显示。
功能点 5：输入系统抽象 — 统一的输入状态模型（throttle/brake/steer 三个轴，值域各为 [-1,1]），键盘与触屏均写入该统一状态；对外暴露单一读取接口，供后续物理/移动逻辑消费；输入状态变更通过受控方法更新，不在渲染循环中直接改内部对象。

## 验收标准
- [ ] 页面加载完成后 2s 内，赛车模型出现在场景中且可见（含车身与 4 个车轮，总三角面数 ≤ 5000，避免过度建模）。
- [ ] 相机初始位置位于赛车后方上方：沿车辆后向水平距离 8~12 单位、垂直高度 3~5 单位，且画面中赛车完整可见、不被裁剪。
- [ ] 按住 W 后 100ms 内赛车开始向前移动，松开 W 后 200ms 内停止加速输入（输入状态归零）。
- [ ] 按住 A 或 D 后 100ms 内赛车开始转向（朝向角速度变化可观测），松开后 200ms 内转向输入归零。
- [ ] 相机跟随：赛车转向 180° 后，相机在 1s 内完成位置/朝向过渡并恢复稳定（无持续抖动），跟随过程中帧率保持 ≥ 55fps。
- [ ] 触屏设备上，虚拟按键 4 个按钮全部可见且可点按；同时按住「加速」与「左转」两个按键时，赛车同时加速并左转（多点触控同时生效）。
- [ ] 键盘 W 与触屏「加速」按键产生完全一致的控制信号（写入同一 throttle 轴，数值一致），A/D 与左/右转向同理。
- [ ] 桌面端（无触摸事件）不渲染虚拟按键；移动端（存在 touchstart 能力）不依赖键盘即可完成加速与转向操作。
- [ ] 全程运行（含键盘连续操作 60s、触屏连续操作 60s）帧率 ≥ 55fps，无内存泄漏（60s 内 JS 堆增长 < 50MB）。

## 边界条件（不做的事）
不包含：赛道模型生成与渲染（路面/路肩/护栏/草地，属其他工单）。
不包含：物理系统（加速/减速/抓地力/碰撞减速），本工单仅实现输入信号与基础移动/转向驱动，供后续物理工单接入。
不包含：计时器、圈数统计、起点/终点检测与单圈结算。
不包含：赛车碰撞体、与边界碰撞处理。
不包含：音频（引擎声/音效）。
不包含：外部 3D 模型导入（glTF/glb/FBX 等），赛车仅用引擎内建几何体组合。
暂不支持：手柄/摇杆输入；竖屏触屏布局优化。
超出范围：车辆外观自定义、多车/多玩家、网络同步。

## 资产需求线索
3D 模型：暂无（赛车用 Three.js 基础几何体组合构建，后续如需精致外观再提供 glTF 模型）。
贴图：暂无（车身用纯色材质，可按车壳/车窗/车轮区分颜色）。
图标：触屏虚拟按键图标 4 个（加速、刹车、左转、右转），若后续需要文字/图形化按键再提供。
音效：暂无。
动画：暂无（车轮旋转动画属后续工单，本工单仅预留车轮子节点）。
字体：暂无。
