# PRD — 实现计时与圈数系统

> 所属需求：WebRacing3D 可玩原型 — 核心玩法验证

## 用户故事
As a 赛车玩家，I want to 在驶过起点线后自动开始计时、跑完一圈后自动结算单圈成绩，So that 我能验证核心玩法闭环并获得可量化的单圈表现反馈。

## 功能需求
1. 起终点检测线：在赛道固定直道位置设置一条垂直于赛道走向的虚拟检测线，采用「车辆位置点跨线 + 行进方向」双条件判定通过事件，避免同帧重复计数。
2. 通过方向判定：车辆沿赛道正向（顺时针/赛道约定方向）跨越检测线记为有效通过；反向（倒车过线）不触发计时或结算。
3. 单圈计时器：维护计时状态（READY 未开始 / RACING 计时中 / FINISHED 已结算），精度毫秒级，从首次有效通过检测线起开始累计。
4. 圈数统计：记录当前圈数（第 N 圈进行中）与已完成圈数；车辆首次有效通过检测线后，圈数从第 1 圈切换到计时状态。
5. 比赛状态机：READY → RACING → FINISHED 单向流转，禁止非法跳转；所有计时/圈数变更必须通过统一 action/service 层，禁止组件直接改状态。
6. 结算展示：完成一圈（第二次有效通过检测线）后立即停止计时，冻结单圈成绩并弹出结算面板。
7. 重新开始：结算面板提供「重新开始」按钮，重置计时器、圈数、赛车位置与朝向至起点，回到 READY 状态。
8. UI 同步：计时器（MM:SS.mmm）、当前圈数、速度表实时刷新，计时数据每帧更新不闪烁。
9. 类型安全边界：检测线判定结果、计时状态等外部/运行时数据用类型守卫或 schema 校验，禁止 any。

## 验收标准
- [ ] 赛车出生后沿赛道正向首次通过起终点线时，计时器从 00:00.000 开始计时，启动误差 ≤ 50ms。
- [ ] 计时器显示格式为 MM:SS.mmm，毫秒位每秒刷新 ≥ 30 次，无跳秒或数值抖动。
- [ ] 赛车沿正向第二次通过检测线时，计时立即停止并记录该圈单圈成绩，成绩误差 ≤ 50ms。
- [ ] 完成一圈后 500ms 内弹出结算面板，面板显示单圈用时（MM:SS.mmm）与「重新开始」按钮。
- [ ] 反向（倒车）通过检测线不触发计时开始、不累计圈数、不触发结算。
- [ ] 同一通过事件防抖：检测线在单次有效通过后 1000ms 内不重复计数（杜绝连续帧误判）。
- [ ] 圈数显示实时正确：计时开始时显示「第 1 圈」，完成一圈后显示「已完成 1 圈」（或圈数 1→2 正确更新）。
- [ ] 点击「重新开始」按钮后 500ms 内完成状态重置（计时归零、圈数归零、赛车复位到起点），并回到可再次计时状态。
- [ ] 计时与圈数 UI 更新期间，画面帧率保持 ≥ 55fps（目标 60fps），无明显卡顿。
- [ ] 在未经过起终点线前（READY 状态），计时器保持 00:00.000，圈数显示不随车辆移动变化。

## 边界条件（不做的事）
不包含：多圈累计计时、历史最佳成绩（Best Lap）持久化与排行榜。
不包含：分段计时（Sector Time）、圈速对比、幽灵车（Ghost）回放。
不包含：后端服务、账号体系、跨端数据同步，全程单机本地运行。
不包含：惩罚性计时（撞墙加时、切弯加时）与赛道裁判规则。
不包含：多条检测线的扇区检测，本工单仅实现一条起终点检测线。

## 资产需求线索
起终点线视觉标识：地面横向标线（可用简单几何平面 + 黑白格贴图实现），赛道上方可选横幅。
计时器/圈数 UI：等宽数字字体（避免毫秒跳动导致的布局抖动），深色半透明底衬。
结算面板：半透明遮罩背景 + 居中面板，标题「单圈成绩」与成绩数字。
音效：冲线提示音（可选，1 条，短促约 0.5s）。
动画：结算面板出现动画（可选，淡入/缩放 200-300ms）。
