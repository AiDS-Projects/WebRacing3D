# PRD — 构建 3D 环形赛道场景

> 所属需求：WebRacing3D 可玩原型 — 核心玩法验证

## 用户故事
As a 玩家，I want 一个封闭的 3D 环形赛道（路面、路肩、两侧护栏、草地），So that 我能沿固定路线完整跑完一圈，并为后续碰撞检测与圈数计时提供中心线数据。

## 功能需求
功能点 1：环形赛道几何体——用程序化方式（Three.js 几何体）生成一条封闭环形赛道，路面沿赛道中心线拉伸，无断点、无交叉、无重叠。\n功能点 2：路肩（Curbs）——在路面两侧边缘各生成一条连续路肩（建议红白相间或纯色），作为赛道边缘视觉标识。\n功能点 3：两侧护栏（Guardrails）——沿赛道中心线两侧等距摆放护栏几何体，形成赛道物理边界视觉。\n功能点 4：草地（Grass）——在赛道外围铺设草地平面，覆盖整个赛道包围盒并留出边距。\n功能点 5：中心线数据——将赛道中心线以独立数据模块导出，每条采样点包含三维坐标（x,y,z）与朝向/切线方向，供后续碰撞检测与圈数检测直接引用。\n功能点 6：共享逻辑沉淀——赛道几何生成、中心线采样、常量配置等公共逻辑沉淀到独立模块（如 track/ 目录），不在组件/入口内联实现；全程类型安全，无 any。

## 验收标准
- [ ] 赛道中心线以独立模块导出（如 src/track/centerline.ts），包含类型定义，代码中无 any 类型（可经 lint/tsc 校验）。\n- [ ] 中心线为闭合曲线：首采样点与末采样点的空间距离 ≤ 0.1 世界单位。\n- [ ] 中心线采样点间隔 ≤ 0.5 世界单位，且采样点总数 ≥ 100。\n- [ ] 每个采样点数据结构包含 position（x,y,z）与 direction/tangent（归一化向量）字段，可供外部模块直接引用。\n- [ ] 路面宽度为可配置常量（默认 12 世界单位），路面沿中心线两侧各延伸 6 单位。\n- [ ] 路肩位于路面两侧边缘，每条路肩宽度为可配置常量（默认 1.5 世界单位），连续覆盖整圈无缺口。\n- [ ] 两侧护栏沿中心线等距分布，护栏数量与中心线采样点数量一致，相邻护栏间距 ≤ 5 世界单位。\n- [ ] 草地平面尺寸 = 赛道包围盒尺寸 + 四周各 50 世界单位边距，完全覆盖赛道无空洞。\n- [ ] 场景仅加载赛道（无车辆、无 UI）时，在 1080p 分辨率中端设备上帧率 ≥ 60fps。\n- [ ] 赛道几何顶点数量通过 tsc 编译与构建（vite build）无错误，可被主入口正常导入渲染。

## 边界条件（不做的事）
不包含：车辆物理、加速/转向/碰撞减速逻辑（属于后续工单）。\n不包含：圈数/起点终点检测与计时实现（本工单仅提供中心线数据，检测逻辑在后续工单消费）。\n不包含：开始/重置界面、速度表等 UI。\n不包含：多赛道切换、开放世界地图、赛道编辑器。\n不包含：网络、后端、账号系统。\n超出范围：赛道装饰物（树木、建筑、广告牌等）、天气/光影特效、音效。

## 资产需求线索
赛道为程序化几何体，建议使用 Three.js 基础材质（MeshStandardMaterial/MeshLambertMaterial）纯色区分：路面（深灰）、路肩（红白/纯红）、护栏（白色/银色）、草地（绿色），无需外部贴图。\n图标：暂无。\n图片/贴图：暂无（如后续需要路面纹理可补充 asphalt 贴图，本工单非必需）。\n音效：暂无。\n动画：暂无。\n模型：无需外部 GLTF/FBX 模型，全部由代码程序化生成。
