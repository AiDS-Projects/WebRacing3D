# PRD — 构建 3D 环形赛道场景

> 所属需求：WebRacing3D 可玩原型 — 核心玩法验证

## 用户故事
As a 玩家，I want 一条固定路线的封闭环形赛道（含路面、路肩、护栏、草地），So that 我能沿唯一路径完整驾驶一圈，为后续计时与圈数检测提供可依赖的场景与赛道中心线数据。

## 功能需求
1. 赛道整体：构建一条封闭环形赛道（环路，无断口），路线固定单一，起点与终点重合于同一位置（起点/终点线），形成完整单圈路径。
2. 路面（Road）：沿赛道中心线生成连续路面网格，路面宽度为固定常量（默认 12 米，可配置），路面法线朝上，无重叠面、无破洞、无 Z-fighting。
3. 路肩（Curb）：路面两侧各生成一条路肩，单条宽 2 米（可配置），颜色/材质与路面可区分，用于标记赛道边界。
4. 护栏（Guardrail）：路肩外侧各生成护栏，护栏沿赛道两侧连续布置，高度 1 米（可配置），作为视觉边界。
5. 草地（Grass）：赛道外围（护栏以外）铺设草地平面，覆盖赛道包围盒向外扩展 ≥ 50 米的范围。
6. 赛道中心线数据（Track Centerline）：程序化生成并导出赛道中心线采样点数组，每个点包含三维坐标（Vector3），相邻采样点间距 ≤ 2 米，数据闭合（首尾点重合或距离 < 0.01 米）；中心线数据沉淀到共享层（shared/types 或 shared/data），通过类型安全接口暴露，供后续碰撞检测、圈数检测模块复用。
7. 起点/终点线：在中心线起始索引（index 0）处标记起点/终点线位置，作为后续圈数检测的锚点。
8. 场景组合：路面、路肩、护栏、草地全部挂载到统一场景图（Scene Graph），采用程序化几何体与占位材质（无需外部美术贴图）。

## 验收标准
1. 页面加载后 3s 内渲染出完整环形赛道场景，浏览器控制台无报错。
2. 赛道中心线采样点数 ≥ 200 个，相邻两点间距 ≤ 2 米，且首尾点距离 < 0.01 米（闭合）。
3. 路面宽度恒为 12 米（误差 ≤ 0.1 米），路肩每条宽 2 米（误差 ≤ 0.1 米），护栏高 1 米（误差 ≤ 0.1 米），三者数值均可通过常量配置修改。
4. 赛道中心线自检：中心线不存在自交（任意两条非相邻线段不相交），路面无重叠面/破面，渲染帧率 ≥ 60fps（在 1920x1080 窗口、独立显卡环境测得）。
5. 中心线数据以类型安全接口导出（类型为 Vector3[] 或等价结构），代码中不含 `any` 类型，通过 TypeScript 编译（tsc）与 ESLint 校验无错误。
6. 中心线数据可从共享层模块 import 获取，供碰撞检测模块调用，接口调用返回的采样点数量与场景实际中心线一致。
7. 草地覆盖赛道包围盒向外扩展 ≥ 50 米的区域，护栏以外不存在无材质黑面或漏铺区域。
8. 起点/终点线位置记录在中心线索引 0 处，坐标可读且与路面起点一致。

## 边界条件（不做的事）
不包含：车辆物理（加速/转向/打滑）、碰撞检测与边界减速逻辑、圈数与计时检测实现、起点/终点线碰撞触发逻辑——以上为后续工单范围。
不包含：多赛道、赛道编辑器、自定义赛道、动态赛道变形。
不包含：美术贴图、光照烘焙、后处理特效、天空盒、粒子特效等视觉增强，本工单使用程序化几何与占位材质。
不包含：移动端/触屏适配与 UI 界面。
不包含：后端、账号、网络联机、存档。
赛道中心线数据仅「生成并提供数据接口」，不实现基于该数据的任何检测算法。

## 资产需求线索
暂无（本工单全部采用程序化几何体与占位颜色材质，无需外部图标/插画/背景图/音效/背景音乐/骨骼动画/粒子特效）。
说明：路面、路肩、护栏、草地均使用 Three.js 内置几何体 + MeshStandardMaterial/MeshBasicMaterial 占位色实现；若后续需要真实贴图，可补充路面沥青、草地、护栏贴图线索。
